Privacy notice

Effective 16 November 2026

Connecting an account, enabling AI, and retaining data are separate choices.

In brief: this public information site cannot read your mail. The private Daymark application stores connected-account data to provide its features. Optional AI processing can send mail history, message bodies and supported attachment text to the configured model destination, but requires separate consent.

1. Scope and responsibility

This notice describes the personal Daymark project maintained by THeORange-ui, including its public information pages and private application. Daymark is not a public hosting service. A separately operated deployment must disclose its own operator, hosting, model destinations and retention arrangements before connecting other people's accounts.

Daymark may appear as Slackssistant, the earlier project name, on Google's authorization screen.

2. Data the application accesses

  • Account identity and authorization: provider account identifiers, name, email address, granted permissions and OAuth access/refresh tokens. Daymark does not receive your Google or Microsoft password.
  • Mail: senders and recipients, subjects, timestamps, snippets, message bodies, threads, folders or labels, read/flag state, attachment metadata and attachment files when retrieved.
  • Contacts and calendars: contact details, calendar and event information when the connected account's permissions and enabled features allow them.
  • Your activity: drafts, searches, rules, preferences, chat messages, reviewed actions, consent records and operational records needed to run and troubleshoot the application.
  • Derived information: search indexes, embeddings, summaries, extracted dates, classifications and account-specific memories when the relevant features are enabled.

Daymark uses these data to display and synchronize your workspace, search information, manage authorized mail/contact/calendar operations, provide requested assistance and maintain reliable operation. Permissions do not mean that every available feature is active.

3. Google access and separate agent authorization

The standard Google connection supports ordinary mail, drafts and sending, plus contacts and calendar features. The optional agent connection requests identity, Gmail read/manage and draft/send permissions, and read-only contacts. It does not request Drive, Calendar, contact-write or permanent-delete permission.

Gmail AI workflows require that separate agent grant as well as in-app AI consent. Human review of an AI-origin action does not switch it to the ordinary grant. Disconnecting agent access locally stops Gmail AI work without disconnecting ordinary Gmail.

4. Optional AI processing and sharing

Before enabling model processing for an account, Daymark shows the configured model endpoint, available routing information and input mode. Consent can cover the full email history, including message bodies and supported attachment text, not only a message currently open. Chat prompts, selected context and account-specific derived information may also be processed to provide the enabled assistance.

Masked text is the default consent option. Masking is best-effort and does not guarantee anonymity or removal of sensitive information. Full-text processing requires an additional choice. Changes to the disclosed destination require renewed consent.

The configured endpoint, and any upstream providers it routes to, receive the submitted material. They may process it outside your country. Their retention and security practices depend on the selected service; this notice does not promise zero retention. The deployment operator must review those terms before enabling processing. Revoking consent stops future eligible work, but cannot recall content already transmitted.

Daymark's use and transfer of Google API data must comply with the Google API Services User Data Policy, including Limited Use. Google user data is not sold, used for advertising, or used to train or improve generalized AI models. A model destination must not be enabled if its data practices conflict with these commitments.

5. Storage and protection

The private application stores synchronized data in its database and downloaded files in its object storage. Depending on the client and settings, browser or desktop caches may retain data locally. Provider grants are encrypted on the server; that is not a claim that all stored mail is end-to-end encrypted.

Access to the personal deployment is restricted. External images in received mail are blocked by default. Operational and audit records support reliability and accountability. No system can guarantee absolute security, and authorized administrators of a self-hosted deployment can access its stored data.

6. Retention, disconnection and removal

  • Pause or revoke AI consent: stops subsequent eligible AI processing. Existing derived data is not automatically erased merely by pausing.
  • Remove AI data: disables AI and removes app-managed derived AI data for the account. Original mail, cached message bodies and attachments are separate.
  • Disconnect agent access: removes the local agent grant, not the grant at Google. Ordinary mail and retained cache remain available.
  • Disconnect the account: clears local provider grants and offers retaining or removing the account's app data. File deletion may finish through background cleanup rather than immediately. Client offline caches also need clearing when removing copies from a device.

Local removal does not delete originals at Google or Microsoft and does not delete material previously received by a model provider. You can also manage access through your provider's account settings. Google-side revocation may invalidate both standard and agent grants in the same project.

The personal deployment keeps seven completed daily encrypted backup snapshots. Data removed from the live application may remain in older backups until those snapshots rotate out; interrupted backups can delay that rotation. Retained offline caches and operator-held migration or recovery checkpoints are separate copies and require explicit cleanup. Removing data from the current workspace is not a promise of immediate erasure from every copy.

7. This public website

These pages contain no account connection, mailbox API, analytics script, advertising, form or tracking cookie added by Daymark. The pages are hosted on GitHub Pages. GitHub may process technical request data such as IP addresses under its privacy statement. Following external links takes you to services with their own policies.

Private mail, credentials and the private workspace address are not included in the published information site. The interface illustration uses only synthetic content.

8. Questions and changes

For access, correction or removal questions, use the support email shown on the Google consent screen or the private contact channel supplied with your deployment. The maintainer's public profile is THeORange-ui on GitHub. Do not submit private mail or credentials in public issues.

This notice will be updated when the project's data practices change. Material new uses of connected-account data require updated disclosure and applicable consent before they are enabled.
